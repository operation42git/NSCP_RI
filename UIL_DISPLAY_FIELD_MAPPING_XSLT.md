# UIL Search Display - XSLT Version Field Mapping Documentation

## Overview
This document describes how the portal displays UIL search results using **XSLT transformation** (based on HTML from "NSCP_RI - Copy" directory). This version uses a different approach than the Angular component-based version.

## Display Flow

1. **UIL Search Form**: User enters Dataset ID, Gate ID, and Platform ID
2. **Search Results Table**: Displays search results with metadata
3. **XSLT Transformation**: When clicking "Open", XML is transformed using XSLT and displayed in a new window

---

## 1. UIL Search Results Table

### Displayed Fields:
- **Request ID**: Internal request identifier
- **Gate ID**: Gate identifier
- **Dataset ID**: Dataset identifier  
- **Platform ID**: Platform identifier
- **Status**: Request status (COMPLETE, PENDING, ERROR)
- **Action**: Buttons for Notes, Open, Download, Poll

## 2. XSLT-Generated eCMR Display

The eCMR display is generated by transforming the XML using an XSLT stylesheet (`eCMR.xslt`). The transformation happens client-side using the browser's `XSLTProcessor` API.

### Transformation Process:

1. **XML Decoding**: Base64-encoded XML data is decoded
2. **XSLT Loading**: XSLT stylesheet is loaded from `/assets/xslt/eCMR.xslt`
3. **Transformation**: `XSLTProcessor.transformToDocument()` transforms XML to HTML
4. **Display**: Resulting HTML is opened in a new browser window

### Key Code (from `uil-search.component.ts`):

```typescript
async open(requestId: string) {
  let index = this.result.findIndex(entry => entry.requestId === requestId);
  let content = atob(this.result[index].data);  // Decode base64
  const style = await this.getAsset('/assets/xslt/eCMR.xslt');  // Load XSLT
  const styleEl = this.parse(style);
  const contentEl = this.parse(content);
  const xsltProcessor = new XSLTProcessor();
  xsltProcessor.importStylesheet(styleEl);
  const resultDocument = xsltProcessor.transformToDocument(contentEl);
  // Open in new window
  let winUrl = URL.createObjectURL(new Blob([resultDocument.firstElementChild.innerHTML], {type: 'text/html'}));
  window.open(winUrl);
}
```

## Comparison with Angular Component Version

| Feature | XSLT Version (NSCP_RI - Copy) | Angular Component Version |
|---------|-------------------------------|---------------------------|
| **Transformation** | Client-side XSLT | Server-side parsing + Angular template |
| **Field Coverage** | ~6 fields mapped | ~28 fields mapped |
| **Goods Table** | Hardcoded sample data | Dynamic from XML |
| **Styling** | Basic table layout | Modern card-based layout |
| **Language** | English labels | Croatian labels (hr.json) |
| **Display Location** | New browser window | Same-page component |

## Recommendations

1. **Update XSLT**: Map individual consignment items from `consignment/includedConsignmentItem` instead of using hardcoded data
2. **Add Missing Fields**: Map Fields 5, 13-15, 19-28 from the XML
3. **Fix Namespace Bug**: Fix the missing namespace prefix on line 88 (`carrier` → `efti:carrier`)
4. **Consider Migration**: The Angular component version provides better field coverage and user experience
